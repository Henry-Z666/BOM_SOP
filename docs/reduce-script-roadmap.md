# reduce_script：降本增效路线

## 目标与边界

目标是降低 Creo 批量出图的等待时间、磁盘占用和人工复核量，同时保持正式图的几何与审计真值不变。

- 最终总装仍是唯一渲染源。
- 仍只使用 `fixed_123` / `fixed_456` 两个产品级视角。
- 保留正向阶段可见性、纯平移爆炸、同 CAD 点箭头、单步独立失败重试和全部正式校验。
- 不采用屏幕坐标自动化，不修改源 CAD，不将低置信推断直接发布。

## 优先级

### R1：一次准备模型，整批复用

现状：`run_bounded_stage_batch.ps1` 每个步骤都会启动一次 `run_stage_batch.ps1`；后者在未传入 `PreparedModelsRoot` 时复制整套 `零件图`。42 个步骤会得到 42 份大体积隔离副本。

改造：每个批次按“权威 ASM SHA-256 + isolated_config.pro 哈希”创建一份只读准备模型目录，顺序步骤共享该目录；每个 J-Link 会话仍独立启动、不保存模型。为每一步保留独立日志、临时目录和输出目录。

硬门槛：每步执行前后校验权威 ASM 哈希；若任何文件被会话修改，立刻废弃共享目录并仅重跑该步骤的全新副本。

预期：将模型复制次数从步骤数降为批次数，显著降低磁盘 I/O 与临时目录占用。

### R2：内容指纹增量渲染

为每个输出定义 `render-input-fingerprint`：权威 ASM 哈希、规范化 job JSON、相机合同、Java 类/源码哈希、Creo 配置哈希和输出帧规则。

- 同一指纹且 JPEG、箭头审计和图片校验均通过时，跳过渲染。
- 只重跑合同、CAD、相机、箭头代码或配置变更影响的步骤。
- SOP 文字或排版变更不得触发 Creo 重渲染。

硬门槛：缓存命中仍执行轻量哈希、尺寸、箭头覆盖和合同版本检查。

### R3：批次指标与可恢复性

增加每步指标：模型准备秒数、Creo 启动秒数、导出秒数、校验秒数、重试次数、输出大小与临时目录大小。

- 产出机器可读 `batch-metrics/v1`。
- 失败只重跑失败 job，不删除已通过的图片与审计。
- 批次结束自动清理通过步骤的会话临时目录，仅保留合同、JPEG、箭头审计、日志摘要和失败现场。

先有基线，再决定是否值得做会话复用或并行。

### R4：双固定视角的几何自动评分

不再依靠手工逐步挑选视角。对 `fixed_123` 和 `fixed_456` 各计算一次投影评分：

- 活动件与接收件的屏幕面积；
- 接收面是否退化为薄线；
- 活动件、接收边界、箭头端点是否都在画框中；
- 投影遮挡与孔阵列最小间距；
- 箭头投影长度与可读性。

达到阈值时自动选择高分视角；两者都低置信时输出两个低分辨率预览并标记复核队列，但不生成第三视角。

### R5：接收面与爆炸方向自动推断

按证据强度解析约束、孔轴与接收面，输出根坐标法向与置信度。

- 高置信：平移严格沿接收面外法向，避免误在面内移动。
- 中低置信：保留候选和证据，进入批次例外清单；不得用猜测覆盖正式合同。
- 同一已完成子装配只从根 occurrence 整体移动。

### R6：从配方生成阶段合同

把产品特定人工修正收敛为小型 `assembly-recipe`：BOM 分组、前置依赖、刚性子装配、必要上下文和明确例外。由生成器自动展开：

- `visible_occurrences`；
- 完成件继承；
- BOM 数量校验；
- 任务顺序与跳步检查；
- 需要单独特写的小合件。

这样避免直接手改数十份 JSON 造成顶板、密封条等顺序跳步。

### R7：谨慎探索会话复用与并行

仅在 R1--R3 数据显示 Creo 启动占主导且单步独立性已验证后，测试：

- 有界长驻 worker：每 3--5 步回收一次 Creo；
- 最多两个并行 worker，并以许可证、内存与文件锁为硬上限；
- 任何污染、锁冲突或输出不稳定立即退回单步独立会话。

这项不是首轮优化，因为稳定性比启动时间更重要。

## 首个迭代建议

先实现 R3 的基线指标和 R1 的批次共享准备目录，然后用当前 42 步合同作 A/B 测试。验收条件：图片、箭头审计和正式校验结果一致；模型复制次数从 42 次下降到 1 次；失败时可只重跑单个 job。
