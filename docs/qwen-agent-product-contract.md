# Qwen Creo 装配 SOP Agent 产品契约

状态：`WORKING BASELINE`  
适用目标：把现有 Creo 装配 SOP 生成器封装为由 Qwen 编排、可无人值守运行的本地 Agent。  
本文定义最终产品效果和验收边界；当前代码通过测试不代表已经满足本文。

## 1. 产品承诺

完成一次系统级安装配置后，用户每次运行只需提供：

1. 一份 BOM 文件；
2. 一个包含 Creo `.asm/.prt` 文件的 CAD 文件夹。

Agent 必须自动完成输入预检、BOM 规范化、最终总装识别、CAD occurrence 扫描、BOM/CAD 映射、安装规划、相机校准、渲染、箭头生成、质量校验、受限纠错、SOP 出版和交付封装。

“全程不用人工介入”的正式含义是：

- 对满足输入契约且所有几何事实可证实的任务，自动生成通过验收的完整交付包；
- 运行过程中不向用户询问技术问题；Agent 先自检、局部纠错和有界重试；
- 单个步骤失败不能停止无关步骤，Agent 必须继续完成所有不依赖该问题的工作；
- 存在多个合理解释且无法自动判定时，Agent 生成少量候选图供用户在最终结果中选择；
- 不得为了产出结果而猜测 CAD 事实、绕过硬门或把疑惑图片标成已确认图片。

系统不能承诺任意错误输入都得到全部正确的图片；系统承诺尽可能完成整个 SOP，并把无法自动消除的疑惑限制在具体步骤。用户释疑后，Agent 只重新生成受影响步骤并更新 SOP，不要求重新跑完整流程。

对外是黑箱：用户不需要理解合同、occurrence、状态机、日志或脚本。内部仍必须保留这些可审计证据，但它们不是最终交付物。

## 2. 部署配置与运行输入

以下属于一次性的系统部署配置，不计入每个产品的用户输入：

- Creo 安装目录、J-Link 运行环境和许可证位置；
- Python、Java 和本地工作目录；
- Qwen/DashScope 模型、API 地址、超时、限流和 Key 环境变量；
- 系统内置 SOP 模板及其版本；
- 允许发送到云端的数据策略。

每次运行的公开入口应等价于：

```text
sop-agent run --bom <BOM.xlsx> --cad-dir <Creo模型目录>
```

可选参数只能改变交付表现或执行资源，例如自定义 SOP 模板、输出目录、继续某次运行；不能要求用户提供流水线内部事实，例如最终总装名、occurrence ID、相机矩阵、爆炸向量或 discovery JSON。

## 3. 不可违反的事实边界

- Qwen 负责理解用户意图、启动批次、读取阶段摘要和选择已授权的恢复策略。
- 确定性程序负责 BOM 解析、文件识别、哈希、CAD occurrence、装配约束、几何计算、状态转换、渲染执行和硬门校验。
- Qwen 的自然语言判断不能成为 CAD 几何、任务完成状态或出版资格的唯一证据。
- 正式几何、位置和相机只来源于锁定的最终总装。
- 源 CAD 只读；所有 Creo 操作使用批次隔离的工作副本且不得回写源文件。
- 所有步骤、产物、输入和模型调用必须有版本、哈希和来源记录。
- 项目不得依赖 GPT、Codex、OpenAI SDK、Codex Skill 运行时或私有会话记忆。
- Qwen 接口必须通过项目自有的 provider adapter；DashScope 原生协议是首个正式实现。

## 4. Agent 状态机

每次运行使用唯一 `run_id` 和独立目录，只允许以下状态前进：

```text
CREATED
  -> PREFLIGHTED
  -> BOM_NORMALIZED
  -> ASSEMBLY_LOCKED
  -> CAD_DISCOVERED
  -> PLAN_VALIDATED
  -> RENDERED
  -> IMAGES_VALIDATED
  -> PUBLISHED
  -> DELIVERED
```

运行级状态不因单张图片失败而进入 `BLOCKED`。每个安装步骤独立保存 `PENDING`、`RUNNING`、`PASSED`、`QUESTIONED`、`FAILED` 或 `DEPENDENCY_WAIT`；运行继续调度所有依赖已满足的步骤。只有系统级输入或环境故障导致没有任何阶段可以继续时，运行才进入 `BLOCKED`。只有确定性验收门可以写入阶段完成标记；Qwen 不得直接修改状态。重新运行时根据输入指纹和完成标记恢复，不依赖聊天历史。

阶段产物采用临时文件加原子重命名；没有完成标记的产物一律视为未完成。源输入、规划规则、程序版本或上游产物哈希变化时，必须使受影响的下游缓存失效。

步骤之间以安装依赖图连接，而不是简单地把第 N 步串行绑定到第 N+1 步：

- 相机、箭头、构图或单次渲染失败是局部表现问题，不改变该步骤的完整安装态，后续步骤可以继续；
- 多个候选方案若具有相同的完整安装态，可以提供候选图并继续所有后续步骤；
- 疑问若会改变 occurrence、数量、安装顺序或完整安装态，只把依赖该事实的后代步骤置为 `DEPENDENCY_WAIT`，其他装配分支继续；
- 释疑后从依赖图计算最小失效子图，禁止无条件重跑全部步骤。

## 5. Skill 架构

Skill 是稳定的批量能力，不是每个 BOM 步骤的一段提示词。正式 Agent 至少需要下列深模块：

| Skill | 唯一职责 | 主要产物 |
| --- | --- | --- |
| `intake-preflight` | 验证两项输入、运行环境和批次隔离 | `input-manifest.json` |
| `normalize-bom` | 解析列、层级、数量、工艺和来源 | `normalized-bom.json` |
| `lock-assembly` | 自动识别并锁定最终总装及版本 | `assembly-manifest.json` |
| `discover-cad` | 递归抽取 occurrence、变换和约束 | `cad-graph.json` |
| `map-bom-cad` | 建立带证据的 BOM/occurrence 映射 | `occurrence-map.json` |
| `plan-assembly` | 生成全部原子安装步骤及依赖图 | `step-plan.json` |
| `clarify-plan` | 汇总生成前确认项并锁定推荐选择 | `clarification-packet.json` |
| `compile-render-jobs` | 生成状态增量、双视角、爆炸和箭头合同 | `render-plan.json` |
| `render-batch` | 以受控 Creo worker 批量出图 | 底图、校准图、箭头审计 |
| `validate-repair` | 执行硬门、视觉门和有界局部重试 | `acceptance-report.json` |
| `publish-delivery` | 动态分页、写入模板并封装交付 | `SOP.xlsx`、交付清单 |
| `resolve-step` | 接收普通语言、候选编号或标注图，释疑并局部再生成 | 新步骤修订和更新后的 SOP |

每个 Skill 必须支持独立调用和调试，并使用统一信封：

```json
{
  "schema_version": "agent-skill-result/v1",
  "skill": "normalize-bom",
  "run_id": "...",
  "status": "passed | retryable | blocked",
  "input_fingerprint": "sha256:...",
  "artifacts": [{"kind": "normalized-bom", "path": "...", "sha256": "..."}],
  "diagnostics": [],
  "retry_scope": null,
  "allowed_next": ["lock-assembly"]
}
```

接口约束：

- 所有 Schema 都有独立版本；消费者拒绝未知主版本。
- Skill 接收 `run_id` 和批次内的逻辑产物引用，不接收任意输出路径。
- 返回给 Qwen 的是数量、状态、错误代码和产物引用摘要，不是数百个 occurrence 的完整上下文。
- 同一输入指纹重复调用必须幂等。
- `retryable` 必须给出机器可执行的 `retry_scope`；`blocked` 必须给出稳定错误代码和证据。
- Skill 可通过 selector 单独执行某个主工序、安装步骤或渲染任务，但正式全流程由状态机决定依赖和失效范围。

Agent 对普通用户只暴露两个深模块接口：

```text
generate(BOM文件, CAD文件夹) -> SOP与步骤图片
resolve(运行标识, 步骤编号, 用户释疑) -> 更新后的SOP与步骤图片
```

`resolve` 接受“第 12 步选 B”“箭头应指向左侧孔位”等自然语言，也可以接受用户选中的候选图或在图片上的标注。内部 Skill 数量、执行顺序、文件合同和恢复过程不暴露给用户。

## 6. 规划与规模边界

必须区分以下概念：

- **主工序**：BOM 中用于 SOP 分组的工序；
- **安装步骤**：一次可独立渲染和验收的原子安装动作；
- **渲染任务**：某安装步骤的一种正式图像输出；
- **运行批次**：从两项输入到交付或阻断的一次执行。

框架必须按至少 100 个主工序、500 个渲染任务设计：

- 步骤状态保存“相对前一步的增量 + 周期检查点”，不得在每个任务重复完整累计可见集；
- 规划输出为依赖图，不能依靠 Qwen 逐步骤循环维持进度；
- Creo worker 在一个准备好的只读模型副本上执行一批任务，不能每张图复制整套模型；
- 并发由 Creo 许可证和稳定性控制，默认 1～2 个 worker；worker 执行有限任务后重启；
- 单步骤失败只重算受影响子图；上游事实变化才使相应下游失效；
- 出版按数据动态分组、分页，不允许硬编码 8 个工作表或固定两位编号。

## 7. 自动纠错边界

允许的自动纠错必须是有界且可审计的，例如：

- 在 `fixed_123` 和 `fixed_456` 之间切换；
- 在合同允许范围内调整平移距离、PAN、ZOOM 和箭头布局；
- 重新启动异常 Creo worker；
- 只重跑失败的安装步骤；
- 对可识别的 BOM 表头、空行和合并单元格应用确定性解析策略。

禁止自动纠错：

- 猜测缺失零件对应哪个 occurrence；
- 猜测接收件、接收面法向或装配顺序；
- 显示未来零件来填补画面；
- 新造第三相机方向；
- 修改 BOM、源 CAD 或硬门阈值来使失败通过。

每个任务的自动尝试次数必须有上限；达到上限后，该步骤进入 `QUESTIONED` 或 `FAILED`，不能无限循环消耗 Qwen API 或 Creo 许可证。运行继续处理所有不受影响的步骤。

### 7.1 候选图规则

只有满足基础硬门但在表达或语义上存在少量合理选择时才能生成候选图。候选必须：

- 通常限制为 2～4 张，并按 Agent 推荐顺序标为 A、B、C、D；
- 每张只改变一个待释疑因素，例如相机、接收位置、箭头布局或安装顺序，不能把多个变量混在一起；
- 具有相同完整安装态时才允许后续步骤沿共同状态继续；
- 在文件名和 SOP 中明确标记“待确认”，不得伪装为正式通过；
- 用户选择后再次通过全部适用硬门，再替换正式步骤图。

如果连基础几何或渲染硬门都无法通过，不能制造候选图。此时 SOP 中保留该步骤的清晰占位，其他步骤继续；Agent 在结果说明中用普通语言指出需要补充的事实。

### 7.2 释疑后重新生成

用户可以在首次运行结束后的任何时间对一个或多个步骤释疑。Agent 必须：

1. 把自然语言、候选编号或标注图转换为版本化的步骤修订；
2. 检查释疑是否足以消除问题，不足时继续保留候选，不修改已通过成果；
3. 只使该步骤及确实依赖其完整安装态的后代失效；
4. 重新规划、渲染、校验受影响部分并更新 SOP；
5. 保证不受影响的已通过图片内容哈希保持不变；
6. 在内部保留旧修订用于追溯，但用户交付目录只显示最新版本。

## 8. 正式交付

面向用户的交付目录只能包含 SOP 和各步骤图片。内部合同、日志、验收报告、Qwen 调用记录和恢复数据保存在 Agent 工作区，不作为交付物出现。

全部步骤通过时：

```text
delivery/<run_id>/
  SOP.xlsx
  步骤图片/
    0001.png
    0002.png
    ...
```

仍有疑惑或失败步骤时也不打断整体交付：

```text
delivery/<run_id>/
  SOP_待确认.xlsx
  步骤图片/
    0001.png
    0002_待确认_A.png
    0002_待确认_B.png
    0003_待重新生成.png
    ...
```

其中 `待重新生成` 可以是清晰占位图，仅用于保持步骤编号和 SOP 图位完整，不能伪装成安装指导图。

要求：

- `SOP.xlsx` 可编辑，安装步骤图同时单独交付；
- 每张图可追溯到 BOM 行、occurrence、相机、箭头审计和源总装哈希；
- 用户目录只保留最终安装图；无箭头底图、校准图和审计文件仅在 Agent 内部保留；
- 所有步骤通过后才使用正式文件名 `SOP.xlsx`；仍有问题时必须使用 `SOP_待确认.xlsx`；
- SOP 内的问题步骤图位必须显示“待确认”或“待重新生成”，不能依赖用户理解文件命名；
- 用户完成释疑后，Agent 更新交付目录为最新版本；全部通过时把 `SOP_待确认.xlsx` 转为 `SOP.xlsx`，候选图从用户目录移除；
- 不默认生成 PDF、JSON、HTML、CSV、日志或开发说明。

## 9. 云端数据边界

默认策略：

- `.asm/.prt` 原文件和完整 CAD 图谱永不发送到云端；
- Qwen 文本模型只接收最小化的 BOM 摘要、阶段摘要、错误代码和规则片段；
- 只有启用视觉复核时，Qwen-VL 才接收渲染图片；
- 所有发送内容记录类型、哈希、模型、时间、用途和响应 ID；
- Key 只从部署环境读取，不写入仓库、批次合同或日志；
- 模型不可用时进入可续跑状态，不得丢失已经通过的确定性阶段。

BOM 文本和渲染图片是否允许发送到 DashScope，必须由部署方确认；未确认时采用最小披露默认值。

## 10. 验收标准

### 10.1 干净迁移测试

在新建且与历史输出隔离的工作区中，只放置 BOM、CAD 文件夹和已安装 Agent：

1. 禁止复制旧产品脚本、旧合同、旧图片或旧缓存；
2. Agent 自动创建批次并从零完成所有阶段；
3. 只允许调用 Qwen/DashScope，不加载 OpenAI SDK、Codex 或 GPT 工具；
4. 源 CAD 在运行前后逐文件哈希一致；
5. 成功输出满足第 8 节的完整交付结构。

### 10.2 确定性测试

同一输入连续运行 10 次：

- 规范化 BOM、最终总装、主工序/安装步骤、occurrence 映射、相机选择、爆炸向量和箭头端点完全一致；
- 图片文件允许编码字节不同，但规范化像素、构图和几何投影必须处于版本化容差内；
- 任何差异都有明确错误代码，不能只给自然语言说明。

### 10.3 规模与恢复测试

- 合成或真实用例至少包含 100 个主工序和 500 个渲染任务；
- 规划、验证和状态保存不得出现随累计可见集导致的二次方合同膨胀；
- 执行过程中强制终止 Agent 和 Creo，重启后不得重跑已确认通过且指纹未变化的任务；
- 修改一个叶子安装步骤时，只重新执行其受影响子图；
- Qwen 上下文不随步骤数线性堆积完整任务明细。

### 10.4 失败测试

至少覆盖缺零件、多个候选总装、BOM/CAD 数量不符、无约束接收件、源总装运行中变化、渲染遮挡、API 超时和 Creo 崩溃。每个用例都必须得到有界恢复、步骤隔离或系统级 `BLOCKED` 之一，且不得把失败图片标为正式通过。

还必须证明：

- 人为使一个局部渲染任务连续失败时，所有无关步骤仍完成；
- 一个疑惑步骤具有共同完整安装态时，Agent 输出 2～4 张候选图并继续后续步骤；
- 一个疑惑会改变完整安装态时，只有依赖它的后代等待，其他分支完成；
- 用户选择候选后只重跑最小受影响子图，不受影响图片哈希不变；
- 全部疑惑解决后，用户目录中只剩 `SOP.xlsx` 和正式步骤图片。

## 12. 推荐开发顺序

1. 建立运行目录、状态机、产物注册表、指纹和统一 Skill 信封；
2. 实现只接收 BOM + CAD 目录的 intake，以及最终总装自动识别；
3. 将 BOM 解析、CAD 映射和规划拆成可扩展的批量深模块；
4. 将 Creo 执行改为可恢复 worker 批处理并落地硬门；
5. 实现动态出版和固定交付包；
6. 接入 DashScope 原生 provider adapter，再让 Qwen 调用批量 Skill；
7. 最后进行干净迁移、10 次确定性、500 任务压力和故障恢复验收。

Qwen 接入排在确定性内核之后：即使暂时移除模型，状态机仍应能按已生成的确定性计划完成渲染、校验和出版。
