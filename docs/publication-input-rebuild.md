# 从资料重建出版输入

入口：`python -m sop_pipeline.agent.publication_rebuild`。

此入口不读取历史工序号、历史实例分配或历史数量来构造新结果。`--history` 仅在新结果完成后生成独立对照报告。

```powershell
python -m sop_pipeline.agent.publication_rebuild `
  --product project-data/cdu900-left/product.json `
  --graph project-data/cdu900-left/analysis/新总装图谱.json `
  --history project-data/cdu900-left/analysis/出版排序内容.json `
  --output work/publication-rebuild-v0
```

加 `--with-qsl` 会重新解析产品配置里的原始工艺卡和参数标准，读取 QSL 物料表数量并关联工艺候选，不复用历史解析包。原料和图片须自行在本地准备；本入口不启动 Creo、不生成图片、不修改源文件。

## 当前 V0 的契约

1. 原始 BOM 层级及层次单元格颜色决定来料边界。最外层黄色来料整体使用，其内部不单独生成物料。
2. 使用现有图号/模型参数匹配器取得 CAD 候选，额外检查父级范围；父级不成立时不接受全局同名候选作为已分配实例。
3. 同时保存本级数量和乘父级数量后的整机数量。整机数量与候选实例数一致、父级范围成立且无重复占用时才自动分配。候选超量不截取前 N 个。
4. 已确认物料按 BOM 构造父项形成部件范围。输出排序是 BOM 来源顺序，不宣称是经过验证的现场安装顺序。没有按螺钉逐项生成出版页。
5. QSL 数量附文件、页签、单元格和哈希；与本级/整机数量分别比较。相同也不能证明适用范围相同；不同也不直接证明整机 BOM 错误。
6. QSL 工艺和力矩作为有来源的候选保存。尚未明确连接及适用范围时，不向其他同型号物料复制力矩。
7. 未确认、未建模和构造上下文均留在分配台账。`missing` 是当前匹配未命中，不等于原料文件缺失，也不代表可以删除该物料。

## 输出

- `出版排序内容.json`：兼容出版顶层字段的未渲染草案；`production_eligible=false`，`status=draft_not_rendered`，`images=[]`。
- `cad-mapping.json`：原始映射候选及依据。
- `历史对照.json`：按 BOM 行比较数量和实例集合，并保存历史每一工序的分组、数量、实例及文字。未记录的历史决策原因不作推断。
- `重建验证.md`：状态汇总、未确认行及 QSL 数量观察。
- `source-analysis/`：开启 QSL 时本次重新解析的资料包。

历史部件出版配方已拒绝直接消费这种草案，避免把新范围编号误当成旧的 366 个工序编号。

## 尚未补通的部分与验收条件

V0 补上可复跑的资料到分配草案入口，尚不是自动生成最终出版输入的完整替代。

- BOM/CAD 层级不一致的实例需基于原生连接关系证明归属，不能借用历史实例 ID。候选数量冲突也需证明各连接归属。
- 无独立模型的耗材需结合 QSL 适用范围形成有来源的领料记录，不能用实例数代替长度或重量。
- QSL 页签对应的部件、连接和先后约束需明确；同料号多页出现不能把所有页数量直接相加或取最大值。
- 自动依赖排序和部件分卡须进入通用模块，替代历史 `scripts/cdu900/plan_component_publication.py` 的固定工序号配方。
- 渲染任务、渲染结果和新工序需通过稳定 ID 关联，验证后才能填入 `images` 并进入出版。

验收应比较新旧的物料行总量、完整实例集合、来料边界和连接覆盖；不要求复刻历史步数。修改 BOM 用量、父级重复数或换一套 CAD 实例路径时，新结果须跟随输入变化，历史数据只能解释差异，不能约束结果。
