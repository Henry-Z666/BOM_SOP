# BOM颜色与装配边界

本项目新版生产BOM“层次”列的实体底色属于工艺输入，不依赖CAD显示颜色或GPT判断。按用户确认约定，`FFFF00`是完整发料物料，`FFC000`表示组织装配的上层范围。约定只适用于本项目的这套资料，不能自动推断其他供应方颜色的意义。

层级决定父子关系，最外层黄色决定停止展开。其内部白色行和嵌套黄色行仍属于完整模型，但不单独生成安装步骤、待装件或重复领料。黄色范围外的白色行保留为工艺上下文，结合工艺卡、工位和CAD证据决定用途，不按白色批量删除。

解析器读取XLSX实体填充的RGB与层级，保存原始行号及颜色。主题色、索引色和条件格式产生的颜色目前不能代替实体RGB；输入来源改用这些形式时须先明确转换规则。

通用流程为：

1. `normalize_bom`保留底色与原始层级；`color_boundary_contract`冻结每行的角色和所属完整物料。
2. BOM映射、草案与正式规划统一使用`assembly_scope_frontier`。橙色框架不能提前作为完整基体显示；从首个完整发料基体逐步构建。
3. 正式计划的`color_boundaries`随序列化、恢复和锁定保留，并参与计划摘要。
4. `compile_locked_render_jobs`在出图前阻止内部行重新进入，任务携带源BOM行和颜色归属证据。旧计划没有此证据时直接拒绝编译，须用当前BOM重建。
5. 标准`publish_delivery`重新核对当前BOM的颜色归属；阶段出版另调用`validate_publication_scope`，阻止内部物料、未计料待装实例和重复计料。代表图显示一处时，物料表按全部安装实例计量；续图不重复领料。
6. 成品独立读取原始工作簿底色与层级，再核对Excel实际物料表。过滤结果不替代独立自检。

颜色只确定物料边界。安装方向、约束、先后依赖、力矩和数量仍分别来自CAD、工艺卡及BOM，不由黄色猜测。缺失新版模型和未证明接收关系的步骤留在范围记录里，不能用旧模型补齐或凑步数。

回归覆盖嵌套黄色、白色外部行、相邻层级、不同发料位置、旧内部行误入、重复领料以及正式计划恢复/锁定/任务编译。
